# Topic Discovery — 연구주제 발굴 파이프라인

아직 프로젝트가 아닌 아이디어를 프로토콜 초안까지 끌고 가는 5단계 파이프라인. ideation-lead가 총괄한다.

## 실행 모드: 파이프라인 (단계 통과 시에만 다음으로)

각 단계는 관문이다. 통과하지 못한 후보를 다음 단계로 보내지 않는다 — 부실한 후보를 프로토콜까지 끌고 가는 비용이 여기서 자르는 비용보다 훨씬 크다.

## 5단계

### 1단계 — 아이디어 생성 (idea-generator)

**먼저 `_team/ideas/_backlog.md`를 읽는다.** 폐기된 아이디어를 다시 생성하면 같은 검토를 반복한다.

10~20개를 발산적으로 생성한다. 이 단계에서는 실현 가능성을 따지지 않는다. 발상 축(자원 출발/문헌 출발/방법 이식/역방향/임상 마찰/정책·경제)을 고루 쓴다.

산출: `_team/ideas/_generated_{YYYYMMDD}.md`

### 2단계 — 문헌 확인 (lit-scout)

각 후보의 문헌 지형을 파악한다. 전수 검색이 아니라 **지형 파악**이 목적이므로, 후보당 리뷰·메타분석·최근 5년 원저 중심으로 가볍게 훑는다.

이 단계에서 명백히 이미 답이 나온 후보는 팀장이 즉시 폐기한다.

**2단계에서 반드시 할 것 (1차 가동에서 얻은 교훈):**
- **preprint가 언급된 후보는 저자명·DOI 양축으로 출판 여부를 확인한다.** preprint만 보고 "미출판"으로 넘기면 3단계까지 검증 비용을 쓰고 나서 이미 출판된 것을 발견한다
- **LLM·AI 방법론 후보는 PubMed만으로 지형이 보이지 않는다. arXiv를 직접 검색한다.** 이 분야의 결정적 선행연구는 PubMed에 없는 경우가 흔하다

### 3단계 — 공백 검증 (gap-analyst) — **최대 관문**

살아남은 후보에 대해 포화도를 조사하고 공백 존재를 **증거로** 판정한다. 통과 조건:
- 검색식·DB·히트수가 기록되어 있다
- 가장 가까운 선행연구를 지목했고, 그것과의 차이를 한 문장으로 말할 수 있다
- 진행 중인 연구(ClinicalTrials.gov·프리프린트)를 확인했다
- **체계적 문헌고찰 후보라면 사전등록부(PROSPERO·OSF Registries·INPLASY·Research Registry)를 확인했다.** PROSPERO는 JS 기반이라 도구로 조회되지 않으므로 **사람이 직접 확인하기 전까지 "공백확인" 판정을 줄 수 없다.** 등록부를 확인하지 않은 SR 후보의 상한은 "부분공백"이다 — 등록만 되고 미출판인 리뷰는 문헌 검색으로 보이지 않는다
- 임상적 의의를 별도로 서술했다 — 아무도 안 한 이유가 중요하지 않아서일 수 있다

여기서 대부분이 탈락하는 것이 정상이다. 통과율이 높으면 검증이 무른 것이다.

### 4단계 — 가설 설정 (gap-analyst + methodologist)

검정 가능한 형태로 정련한다. 필요 데이터와 접근 가능성을 확인한다. **접근할 수 없는 데이터를 전제한 가설은 보류**로 돌린다 — 폐기가 아니라 보류다. 데이터 사정은 바뀐다.

### 5단계 — 프로토콜 초안 (methodologist)

`design-study`·`calc-sample-size`·`write-protocol`로 설계·표본수·분석계획 초안을 만든다. 완성본이 아니라 랩미팅에서 판단할 수 있는 수준이면 된다.

adversarial-reviewer를 한 번 통과시킨다 — 랩미팅에서 지적당할 것을 미리 잡는다.

## 아이디어 카드

각 후보는 `_team/ideas/I{NN}_{slug}.md` 하나를 가진다. 템플릿은 `assets/IDEA_TEMPLATE.md`.

**단계(stage):** `generated` → `screened` → `gap-verified` → `hypothesis` → `protocol` → `adopted` / `parked` / `dropped`

`_team/ideas/_backlog.md`에 한 줄씩 색인한다.

## 탈락 처리

**탈락한 아이디어를 삭제하지 않는다.** `parked`(보류, 재개 조건 명시) 또는 `dropped`(폐기, 사유 명시)로 카드를 남긴다. 6개월 뒤 데이터 사정이 바뀌면 되살아나고, 같은 아이디어를 두 번 검토하는 낭비도 막는다.

## 기존 스킬 재사용

이 파이프라인은 절차를 새로 만들지 않고 기존 스킬을 호출한다: `ma-scout`(메타분석 주제 발굴), `find-cohort-gap`(코호트 DB 공백), `author-strategy`(연구 궤적 분석), `search-lit`, `design-study`, `calc-sample-size`, `write-protocol`.

## 에러 핸들링

| 상황 | 대응 |
|------|------|
| 생성 후보가 전부 기존 연구와 중복 | 그대로 보고한다. 새로워 보이는 변형을 억지로 만들지 않는다 |
| 문헌 검색 실패 | 미검증으로 표시하고 3단계로 보내지 않는다 |
| 공백 판정이 애매 | `부분공백`으로 두고 랩미팅 토론 안건으로 올린다 |
| 데이터 접근 불가 | `parked` + 재개 조건 명시 |
| 후보가 팀 범위 밖 | `dropped` + 사유 |

## 테스트 시나리오

**정상:** "관상동맥 CT 쪽에 새 주제 없을까" → 백로그 확인 → 15개 생성 → 문헌 확인에서 6개 즉시 탈락 → 갭 검증에서 3개만 통과(각각 검색식·최근접 선행연구·NCT 확인 기록) → 가설 정련 → 2개가 프로토콜 초안 도달 → 랩미팅 상정.

**에러:** 갭 검증에서 "선행연구 없음"이라 주장하나 검색식이 기록되지 않음 → 팀장이 반려. 검색이 부실해서 안 보이는 것과 실제로 없는 것을 구분하지 못하면 이미 나온 논문을 반복하게 된다.
