# Project Intake — 프로젝트 등록·카드 생성

연구 프로젝트를 팀의 관리 대상으로 만드는 스킬. 산출물은 `projects/{id}_{slug}/PROJECT.md` 카드 하나이며, 이 카드가 팀장의 역할 정의가 된다.

## 왜 카드가 먼저인가

팀장은 공용 템플릿 하나로 정의되어 있고, 어떤 프로젝트의 팀장인지는 주입되는 카드가 결정한다. 카드가 부실하면 팀장은 일반론만 수행한다. 카드는 팀 전체의 성능을 좌우하는 단일 지점이다.

## 워크플로우

### Step 1: 유형 판정

| 상황 | 경로 |
|------|------|
| 폴더도 세션 기록도 없는 새 아이디어 | Step 3(대화로 카드 작성) → 3-1(폴더와 팀장 임명 문서) → 4(등록·팀 배정·화면 확인) |
| 기존 작업 폴더가 있음 (이전 대상) | Step 2 → 3 → 4 전부 |
| 이미 팀에 있으나 카드가 낡음 | Step 2(로그만) → 3(갱신) |

### Step 2: 상태 복원

**폴더 실물에서 복원한다** — 파일 목록·수정 시각·기존 README·메모·분석 코드·결과 파일을 보고
마지막 활동 일자, 어디까지 했는지, 무엇이 남았는지를 판정한다. (정식판에는 Claude 대화 기록을 요약해 주는 도구가 있으나 경량판에는 없다.)

**추론으로 채우지 않는다.** 로그와 파일에서 확인되지 않는 항목은 `[확인 필요]`로 남긴다. 잘못된 상태 기록은 팀장을 잘못된 방향으로 보내며, 빈칸보다 해롭다.

### Step 3: 카드 작성

`projects/_template/PROJECT.md` 를 복사해 채운다(서식은 이것 하나다). 분량은 A4 한 장 이내로 유지한다 — 팀장이 매 실행 시작에 읽는 문서이므로 길면 핵심이 묻힌다.

채울 수 없는 항목은 지우지 말고 `[확인 필요]`로 남긴다. 팀장이 그 항목을 발견하면 총괄팀장을 통해 사용자에게 질문한다.

### Step 3-1: 프로젝트 폴더 CLAUDE.md 생성

`projects/_template/CLAUDE.md` 를 복사해 `projects/{id}_{slug}/CLAUDE.md` 를 만들고 `{{…}}` 자리를 채운다. **'이 세션의 역할' 절이 그 폴더에서 연 창을 팀장으로 만든다 — 빠뜨리면 팀장 창이 자기를 모른다.** 카드 서식은 `projects/_template/PROJECT.md`.

이유: 팀장이 그 폴더의 파일을 읽는 순간 이 파일이 자동으로 컨텍스트에 들어온다. 프로젝트 카드를 먼저 읽으라는 지시와, 임의로 바꾸면 안 되는 범위 결정(PI 승인 사항 등)을 여기 둔다. 내용을 카드와 중복시키지 않는다 — 카드로 가는 포인터와 불변 규칙만 담는다.

### Step 4: 등록

1. **팀 배정** — `_team/teams.yaml` 에서 `project: null` 인 팀 하나를 고른다(사용자에게 묻거나 첫 미배정 팀). 약어(`code`)를 정한다 — 영문 대문자·숫자·하이픈 3~10자
2. `_team/registry.yaml` 에 항목 추가: id, slug, title, type, stage, priority, path, **team, code, label(`팀이름_약어`)**, blockers, next, updated, open_items(빈 목록)
3. `_team/teams.yaml` 의 그 팀에 project(제목)·code·label·stage·legacy_id(id) 를 채운다 — **등록부와 팀 정의 둘 다 고쳐야 현황판에 새 팀 줄이 뜬다**
4. `python3 _team/scripts/portfolio.py --write` 로 포트폴리오 표 갱신, `python3 _team/dashboard/refresh.py` 로 현황판 갱신
5. 신규 등록 사실을 `_team/decisions.md` 에 한 줄 기록
6. **화면으로 확인** — 현황판에 `팀이름_약어` 줄이 진행 중으로 보이면 등록이 끝난 것이다

### Step 5(이전 시): 폴더 이동 — 사용자 승인 필수

폴더 이동은 되돌리기 비용이 있고 동기화 폴더라면 재동기화를 유발한다. 반드시 사용자 승인 후 실행하며, 다음 순서를 지킨다:

1. 대응하는 세션 로그 디렉토리명을 먼저 확인해 기록한다 (이동 후에는 매칭이 어려워진다)
2. Step 2의 다이제스트를 **이동 전에** 생성한다
3. `mv "<원본>" "<projects/{id}_{slug}>"` — 복사가 아니라 이동. 두 벌이 남으면 곧 어느 쪽이 최신인지 알 수 없게 된다
4. 이동 후 폴더 내 절대경로 참조(CLAUDE.md, 스크립트, 노트북)를 검색해 갱신한다:
   ```bash
   grep -rl "<옛 상위 폴더 이름>" "<새 경로>" 2>/dev/null
   ```
5. git 저장소면 그대로 동작한다(경로만 바뀜). 리모트·훅에 절대경로가 있는지만 확인한다
6. 카드에 "원본 위치"와 "이전 일자"를 기록한다 — 되돌릴 때와 옛 로그를 찾을 때 필요하다

## 산출물

- `projects/{id}_{slug}/PROJECT.md`
- `projects/{id}_{slug}/CLAUDE.md` (5줄 이내 포인터)
- `projects/{id}_{slug}/_workspace/digests/*.json`
- `_team/registry.yaml`, `_team/portfolio.md` 갱신

## 에러 핸들링

- 세션 로그 없음 → 파일 실물만으로 카드 작성, "세션 기록 없음" 명시
- 한 로그에 여러 프로젝트가 섞임 → 프로젝트별로 분리하고 분리 불가 항목은 양쪽에 참조로 남김
- 폴더 이동 중 실패 → 원본을 그대로 두고 중단. 부분 이동 상태로 두지 않는다
- 프로젝트 ID 중복 → 다음 번호를 부여하고 registry에서 확인

## 테스트 시나리오

**정상:** "AI_ECG meta_SR 폴더를 팀에 등록해줘" → 세션 디렉토리 확인 → 다이제스트 생성 → 폴더 실물 확인(00_admin~08_logs 구조에서 SR 단계 판정) → 카드 작성(단계: protocol, 다음: 검색전략 확정) → registry 등록 → 이동은 사용자 승인 후 실행.

**에러:** 세션 로그가 없는 폴더 → 파일 수정시각으로 마지막 활동일만 기록, 연구 질문은 `[확인 필요]`로 남기고 사용자에게 질문. 폴더 내용만 보고 연구 질문을 지어내지 않는다.
