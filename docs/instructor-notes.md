## 60분 판 — VS Code 에서 Claude Code 로 (터미널 없음)

| 분 | 무엇 | 참석자 화면 |
|---|---|---|
| 0–8 | **왜 팀인가** 세 문장 — 창이 자리다 · 말로 전하면 사라진다 · 생성한 쪽이 검증하지 않는다. 강사 화면으로 정식판 현황판 30초 | 종이 [워크시트](worksheet.md) ①②③ 채우기 (병행) |
| 8–15 | 폴더 열기 | GitHub → **Code → Download ZIP** → 압축 풀기 → **VS Code → 폴더 열기** (`ai_research_team_light-main`) → Claude Code 창. 첫 입력: "설치 확인 돌려 줘" |
| 15–25 | `/setup` | 워크시트 ①의 답을 하나씩. 관심 영역은 말로 하면 총괄이 검색식을 만든다 |
| 25–32 | `/hands-on` 2·3단계 | 본보기 현황판 열기 → 워크시트 ②로 내 연구 등록 → 현황판에 내 팀 줄 |
| 32–40 | **3½단계 — 연구원 하나를 내가 정의** | 워크시트 ③ 한 명. '하면 안 되는 것' 셋은 참석자가 직접 |
| 40–50 | 4·5·6단계 | 새 대화창(프로젝트 폴더) → "당신은 누구입니까" → 내가 만든 연구원 부르기 → `report.py` 보고 → 현황판 갱신 |
| 50–56 | 7단계 (시간 남으면) | 수집 → 발굴 현황판 → 보류 한 번 |
| 56–60 | 마무리 세 문장 + 집에서 할 일 | |

참석자가 입력할 프롬프트는 [실습 프롬프트](prompts.md)에 순서대로 있다. VS Code 대신 Claude 앱의 Code 탭으로 폴더를 열어도 같다.

**사전 공지문 (전날):** ① Claude 앱 설치 + 유료 계정 로그인 확인 ② 아래 주소에서 ZIP 내려받아 압축 풀어 오기 — `https://github.com/JeonKH81/ai_research_team_light` (Code → Download ZIP) ③ 윈도우는 Python 3.9+ 설치(설치 때 *Add to PATH* 켜기). 이 셋이 안 돼 있으면 20분이 사라진다.

**윈도우 참석자:** 실기기 시험이 안 된 상태다. 현황판 생성이 실패하면 강사 화면을 보게 하고, 프롬프트 프로젝트 문서로 넘긴다.

# 강사노트 — 진행자용

핸즈온 대본은 [핸즈온.md](handson.md), 설치는 [설치.md](install.md).
이 문서는 **진행자만** 봅니다. 참석자는 임상의·의학연구자이고 컴퓨터 전공이 아닙니다.

**진행 원칙 셋**
- **전산 용어를 쓰지 않습니다.** 무엇을 하는지로 말하고, 그것이 무엇으로 만들어졌는지는 말하지 않습니다.
  통계·방법론 용어(QUADAS-2·PRISMA-DTA·PRESS)는 그대로 씁니다 — 그게 오히려 정확합니다.
- **한 번에 한 단계만.** 두 단계를 미리 설명하면 손이 따라오지 못합니다.
- **화면을 먼저 보여 주고 설명은 한 줄.** 원리 설명이 길어지면 "아" 지점의 효과가 죽습니다.

---

## 시간표 (총 40분 · 여유 5분)

| 분 | 단계 | 진행자가 하는 일 |
|---:|---|---|
| 0–5 | **설치 마무리** | 시작 전에 이미 내려받아 두게 합니다. `check.py` 를 다 같이 한 번 |
| 5–7 | 0. 설치 확인 | `✗` 인 사람 손들게 하고 개별 대응. "설치는 정상. 다음은 /setup" 이 나오면 정상입니다 |
| 7–15 | 1. `/setup` | **가장 오래 걸리는 곳.** ④ 관심 영역에서 시간이 샙니다(아래 참조) |
| 15–17 | 2. 현황판 둘러보기 | "이 화면은 손으로 그리지 않습니다" 한 줄. 팀 줄을 눌러 보게 합니다 |
| 17–23 | 3. 내 연구 등록 | **첫 "아" 지점.** 현황판을 다시 만들어 줄이 바뀌는 것을 꼭 보여 줍니다 |
| 23–26 | 4. 팀장 창 열기 | 새 터미널. "당신은 누구입니까?" 는 다 같이 |
| 26–31 | 5. 연구원 부르기 | Scout 기다리는 동안 원칙 설명(생성한 쪽이 검증하지 않는다) |
| 31–35 | 6. 보고·현황판 | **둘째 "아" 지점.** 창 두 개를 나란히 놓고 보여 줍니다 |
| 35–45 | 7. 발굴 | **셋째 "아" 지점.** 수집은 30초, `/topic-discovery` 가 3~5분 |
| 45– | 8. 랩미팅 | 시간이 남을 때만. 없으면 마무리 세 문장으로 |

30분짜리로 줄여야 하면 **5단계의 Critic 과 8단계**를 뺍니다. 3·6·7단계는 빼지 않습니다 — 세 "아" 지점입니다.

## 막히기 쉬운 곳과 대처

### 시작 전 (미리 공지할 것)

내려받기와 `python3 install.py` 까지는 **오기 전에** 끝내 오도록 공지합니다. 여기서 막히면 20분이 날아갑니다.

**사전 공지문에 넣을 것(특히 윈도우):** ① Python 3.9 이상(설치 때 PATH 추가 켜기) ② Git(맥은 기본, 윈도우는 Git for Windows) ③ Claude Code 설치 + **유료 계정**으로 `claude` 로그인 확인 ④ 윈도우는 PowerShell 만 씁니다 — 설치 문서의 '윈도우에서는' 절을 링크. **행사 전에 윈도우 참석자 한 사람에게 `python install.py` 결과 화면을 미리 받아 보십시오.** 맥에서 통과한 것이 윈도우·병원망 통과를 뜻하지 않습니다.
`claude --version` 과 `python3 --version` 이 답하는지만 확인해 오게 합니다.

### 0단계 — 확인 결과에 `✗` 가 여럿

| 증상 | 대처 |
|---|---|
| `pyyaml 없음` | `python3 install.py` 를 다시. 그래도 안 되면 `.venv` 안내(설치 문서 2단계) |
| `ANTHROPIC_API_KEY 없음` 이 `✗` | 그 창에서 `unset ANTHROPIC_API_KEY`. 열쇠가 있으면 구독 로그인이 꺼집니다 |
| `claude` 명령 없음 | 이 사람은 옆자리와 화면을 같이 보게 하고 진행을 멈추지 않습니다 |
| 현황판 파일 없음 | `python3 _team/dashboard/refresh.py` 한 번 |

### 1단계 — `/setup` ④ 관심 영역에서 시간이 샙니다

**가장 흔한 사고: 검색식이 너무 넓습니다.** "인공지능"·"machine learning" 만 넣으면 하루 수백 건이 잡히고,
그러면 7단계가 쓸모없는 목록이 됩니다. **하루 5~30건**이 목표라고 미리 못 박고,
개념 묶음 둘을 AND 로 묶게 합니다 — 예: (내 전공 낱말들) AND (인공지능 낱말들).
총괄팀장이 만든 검색식을 **반드시 미리보기 건수로 확인**시킵니다. 0건이면 낱말을 빼고, 수백 건이면 묶음을 더합니다.

관심 영역은 **1개면 충분합니다.** 3개를 다 채우려다 시간이 갑니다.

### 4단계 — 팀장 창이 자기를 못 알아봅니다

"저는 Claude 입니다" 같은 답이 나오면 **폴더가 틀린 것**입니다. 그 창에서 `pwd` 를 쳐 보게 합니다 —
`projects/<폴더>` 안이어야 합니다. 연구실 뿌리에서 열었거나 한 칸 더 들어간 경우가 대부분입니다.
그 폴더에 `CLAUDE.md` 가 있는지도 봅니다(`ls`). 3단계 등록이 끝나야 생깁니다.

여기가 설명하기 가장 좋은 자리입니다 — **폴더가 곧 임명**.

### 6단계 — 보고가 안 들어갑니다

`report.py status` 뒤에 오는 것은 **팀 이름**(`Mercury`)이지 프로젝트 폴더 이름이 아닙니다.
`[팀장 창]` 에서 돌릴 때는 경로가 `../../_team/scripts/report.py` 입니다 — 연구실 뿌리에서 돌리면 `_team/scripts/report.py`.
잘못 쳤으면 다시 치면 됩니다. 되돌릴 일은 없습니다.

### 7단계 — 수집이 0건입니다

둘 중 하나입니다.

- **정말 새 문헌이 없다** → `--days 30` 으로 늘립니다. 대부분 여기서 해결됩니다.
- **받아오지 못했다** → 화면에 `CERTIFICATE_VERIFY_FAILED` 가 보입니다. 병원망·회사망이 통신을 열어 보고
  자기 신분증으로 다시 봉하기 때문입니다. `python3 install.py  (인증서 부품을 넣는다 — 맥에서 그래도 안 되면 zsh _team/scripts/fix_certificates.sh)` 를 한 번 돌리고 다시 수집합니다.
  **이 둘을 구별해서 말해 주는 것이 중요합니다** — "조용하다"와 "못 받아왔다"는 다릅니다.

병원 무선망에서 하는 워크숍이면 **인증서 문제를 미리 겪는다고 보고** 0단계 뒤에 다 같이 한 번 돌려 두는 편이 낫습니다.

### 7단계 — `/topic-discovery` 가 오래 걸립니다

3~5분이 정상입니다. 기다리는 동안 발굴 현황판을 열 **세 번째 터미널**을 미리 준비시키고,
발굴 라인이 왜 따로 있는지 설명합니다(현황판의 축이 다릅니다 — '지금 무엇이 돌고 있는가'가 아니라
'다음에 무엇을 시작할 것인가'). 후보 프로젝트 문서가 생기기 전에 `ideas_server.py` 를 열면 화면이 비어 보이므로
**프로젝트 문서가 만들어진 뒤에** 열게 합니다.

## 참석자에게 던질 질문 셋

넘어가기 전에 던지고, 답이 나오지 않으면 그 자리에서 보여 줍니다.

1. **(4단계 뒤)** "이 두 창은 같은 기억을 갖고 있을까요?"
   → 아닙니다. 그래서 6단계의 보고가 필요합니다. 창을 옮기기 전에 남기지 않으면 사라집니다.

2. **(6단계 뒤)** "현황판의 숫자가 틀렸다면 어디를 고쳐야 할까요?"
   → 화면이 아니라 **프로젝트 문서**입니다. 화면은 프로젝트 문서에서 매번 다시 그려지므로, 화면을 고쳐 봐야 다음에 지워집니다.

3. **(7단계 뒤)** "내가 쓴 원고를 나에게 검토시키면 무엇이 문제일까요?"
   → 만든 문맥 안에서는 자기 전제를 의심하지 못합니다. 그래서 생성한 쪽이 검증하지 않습니다.
   덧붙일 것: 연구 대상 자체가 언어모델인 연구에서는 언어모델을 판정자로 쓰지 않습니다 — 순환논증입니다.

## 정식판으로 넘어갈 때 설명할 것

마무리에 1~2분. **기능 목록을 읽지 말고, 경량판에서 불편했던 것과 짝을 지어** 말합니다.

| 오늘 이렇게 했다 | 정식판에서는 |
|---|---|
| 문헌 수집을 손으로 돌렸다 | 매일 정해진 시각에 저절로 돕니다. 아침 브리핑과 랩미팅 준비도 함께 |
| 노트북 한 대에서 했다 | 컴퓨터 두 대에 같은 연구실을 두고, 정해진 시각 작업은 **한 대만** 맡습니다 |
| Critic 한 명이 검토했다 | 다른 회사 모델이 제2검토자 자리에 들어갑니다 — 이중 선별·자료추출 검증. 연구 대상이 언어모델이면 쓰지 않습니다 |
| 바꿀 것을 그 자리에서 확정했다 | 저절로 도는 것은 **제안만** 올리고 채택은 사람이 합니다. 되돌리기 어려운 일은 도구 단계에서 막습니다 |
| 현황판을 내 컴퓨터에서 열었다 | 인터넷 사본을 두고 폰에서도 봅니다 |

덧붙일 한 줄: **경량판에서 익힌 세 가지(폴더가 곧 임명 / 보고는 파일로 / 현황판은 다시 그려진다)는 정식판에서도 그대로입니다.**
정식판이 더하는 것은 원리가 아니라 **손이 덜 가게 하는 것**입니다.

정식판은 GitHub `JeonKH81/ai_research_team`(비공개·초대제)에 있습니다.

## 진행자 준비물

- 화면 두 개(또는 창을 좌우로 나눈 화면 하나) — `[총괄 창]` 과 `[팀장 창]` 을 나란히 보여 줘야 6단계가 삽니다
- 미리 한 바퀴 돌려 본 연구실 하나 — 7단계가 느릴 때 결과를 대신 보여 줍니다
- 참석자가 등록할 **연구 한 문장**을 미리 생각해 오게 공지 (3단계에서 여기서 막히는 사람이 많습니다)
