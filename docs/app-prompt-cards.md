# 나의 AI 연구실 만들기 — Claude 앱 판 (프롬프트 카드 9장, 60분)

컴퓨터에 아무것도 설치하지 않습니다. **Claude 앱(또는 claude.ai)** 에서 아래 카드를 **순서대로 하나씩** 붙여 넣습니다.
카드마다 "붙여 넣을 것" · "보여야 하는 것" · "왜" 가 있습니다. `[ ]` 안은 자기 것으로 바꿔 넣습니다.

> 앱에서는 파일이 남지 않으므로 **Projects 기능**을 폴더 대신 씁니다. 0번 카드가 그것입니다.
> 집에 가서 파일로 굴리고 싶으면 이 저장소(`ai_research_team_light`)를 Claude Code 로 여시면 같은 구조가 파일로 돕니다.

| 시간 | 카드 | 무엇을 |
|---|---|---|
| 0–10분 | (강사) | 왜 "팀"인가 — 창이 자리다 · 말로 전하면 사라진다 · 생성한 쪽이 검증하지 않는다 |
| 10–15 | 0·1 | 연구실 열기, 총괄팀장 임명 |
| 15–22 | 2 | 내 연구 하나 등록 |
| 22–30 | 3 | **연구원 셋을 내가 정의한다** ← 오늘의 핵심 |
| 30–36 | 4 | 팀장으로 바꿔 앉기 |
| 36–44 | 5·6 | Scout 부르기 → Critic 이 공격 |
| 44–50 | 7 | 보고 → 현황판이 그려진다 |
| 50–56 | 8 | 발굴 — 후보 셋, 판정 |
| 56–60 | 9 | 마무리 세 문장 |

## 카드 0 — 연구실을 연다 (Projects)

앱 왼쪽 **Projects → 새 프로젝트**. 이름은 `나의 AI 연구실`. **프로젝트 지침(Instructions)** 칸에 아래를 통째로 붙여 넣고 저장합니다. 그 뒤 이 프로젝트 안에서 **새 대화**를 엽니다.

```
당신은 내 "1인 AI 연구실"의 총괄팀장이다. 이 연구실의 규칙:

1. 자리. 이 대화창이 총괄팀장이다. 프로젝트마다 팀장이 있고, 연구원(Scout·Planner·Analyst·Writer·Critic 등)은 필요할 때만 불려 나온다. 연구원은 내가 정의한 대로만 움직인다.
2. 기록. 말로 전한 것은 사라진다. 프로젝트의 상태는 언제나 "카드" 한 장(연구 질문·설계·현재 단계·다음 할 일·기다리는 것)으로 유지하고, 상태가 바뀌면 카드를 다시 보여 준다.
3. 검증. 생성한 쪽이 스스로 검증하지 않는다. 문헌·분석·원고가 나오면 Critic 을 한 번 통과시킨다. 인용은 실재를 확인한 것만 쓰고, 확인 못 한 것은 [미확인]으로 표시한다. 숫자를 지어내지 않는다.
4. 말. 나는 임상의다. 전산 용어(프롬프트·토큰·API·에이전트·컨텍스트)를 쓰지 말고 무엇을 하는지로 말한다. 통계·방법론 용어는 그대로 쓴다. 결론부터, 짧게.
5. 결정. 채택·보류·폐기, 설계 변경, 외부 제출은 내가 정한다. 당신은 선택지와 근거를 올린다.
6. 팀 이름은 10개로 고정하고 "팀이름_약어" 로 부른다. 프로젝트가 끝나면 같은 팀이 다음 프로젝트를 받는다.

내가 무엇을 하자고 하면 그 규칙 안에서 진행하고, 판단이 갈리는 지점만 나에게 묻는다.
```

**보여야 하는 것:** 없음 — 지침은 조용히 깔립니다. **왜:** 이것이 Claude Code 의 `CLAUDE.md` 에 해당합니다. 규칙을 대화마다 다시 말하지 않아도 되게 합니다.

## 카드 1 — 총괄팀장 임명과 설치 문답

```
연구실을 연다. 당신이 총괄팀장이라는 것을 한 줄로 확인하고, 아래 다섯을 하나씩 물어라. 한 번에 하나만.
① 연구실 이름 ② 내 전공 ③ 팀 이름 규칙 — 태양계 10개가 기본, 원하면 내가 다른 열 개를 준다 ④ 발굴팀 관심 영역 1~2개와 어디서 찾을지(PubMed / 프리프린트 / 임상시험 등록) ⑤ 랩미팅을 할지, 한다면 간격과 요일
다 받으면 "연구실 설정" 표 한 장으로 정리해 보여 줘.
```

**보여야 하는 것:** 질문 다섯 개가 **하나씩** 오고, 끝에 설정 표. **왜:** 시스템의 값을 사람이 정한다는 것 — AI가 정하는 게 아닙니다.

## 카드 2 — 내 연구 하나 등록

```
프로젝트를 하나 등록한다. 내 연구 질문: [지금 하고 있거나 해 보고 싶은 연구를 한 문장으로]
자료: [있음/없음 — 있으면 무엇]. 단계: [착상 / 설계 / 자료 / 분석 중 하나]
카드 한 장으로 정리해 줘 — 연구 질문 · 설계(모르면 [확인 필요]) · 현재 단계 · 다음 할 일 3개 · 기다리는 것. 미배정 팀 하나에 배정하고 "팀이름_약어" 를 정해 줘. 모르는 칸은 지어내지 말고 [확인 필요]로 둬.
```

**보여야 하는 것:** 카드 한 장, 팀 이름(예: `Terra_HF-READM`), 빈칸은 `[확인 필요]`. **왜:** 카드가 정본입니다. 모르는 것을 모른다고 적는 것이 첫 번째 규칙.

## 카드 3 — 연구원 셋을 내가 정의한다 ★ 오늘의 핵심

종이 워크시트에 적은 셋을 하나씩. **"절대 하면 안 되는 것"은 반드시 내가 씁니다.**

```
이 연구에 필요한 연구원 셋을 정의한다. 내가 말하면 당신이 "연구원 정의 카드"로 써 줘 — 이름 · 하는 일 · 받는 것 · 내놓는 것 · 절대 하면 안 되는 것 셋 · 언제 나를 멈춰 세워야 하는가.

첫째: [예: 문헌 정찰자 — 검색식을 만들고 선행연구를 찾는다. 하면 안 되는 것: 확인 안 된 논문을 인용하는 것]
둘째: [예: 방법론자 — 설계와 표본수를 정한다. 하면 안 되는 것: 자료를 본 뒤 가설을 바꾸는 것]
셋째: [예: 비판자 — 리뷰어처럼 공격한다. 하면 안 되는 것: 근거 없이 지적하는 것, 문제가 없는데 억지로 만드는 것]

셋 다 쓰고 나면, 내가 빠뜨린 "하면 안 되는 것"이 있으면 제안하되 내가 고르게 해 줘.
```

**보여야 하는 것:** 정의 카드 셋. **왜:** AI literacy 의 알맹이 — 역할은 능력이 아니라 **경계**로 정의됩니다. 무엇을 시키느냐보다 무엇을 못 하게 하느냐가 연구의 안전을 정합니다.

## 카드 4 — 팀장으로 바꿔 앉기

같은 프로젝트에서 **새 대화**를 엽니다(폴더를 바꾸는 것과 같습니다). 첫 줄:

```
지금부터 이 대화창은 [팀이름_약어] 팀의 팀장이다. 총괄이 아니다. 내가 방금 만든 카드는 이것이다: [카드 2 의 카드를 붙여 넣기]
당신은 누구이고, 이번 주에 할 구체적 행동 셋은 무엇인가? "분석을 진행한다" 수준이 아니라 "○○ 검색식으로 PubMed 에서 최근 5년 선행연구를 찾는다" 수준으로.
```

**보여야 하는 것:** "저는 ○○ 팀의 팀장입니다" + 구체적 행동 셋. **왜:** 창이 곧 자리입니다. 새 창은 앞 창을 기억하지 못하므로 **카드를 붙여 넣어야** 합니다 — "말로 전하면 사라진다"를 몸으로 겪는 순간.

## 카드 5 — Scout 을 부른다 (팀장 창에서)

```
카드 3에서 정의한 문헌 정찰자를 불러라. 이 연구 질문의 선행연구를 찾을 검색식을 만들고, 웹 검색으로 실제 논문 5편을 찾아 표로 정리해 줘 — 제목 · 첫 저자 · 연도 · 저널 · 한 줄 결과 · 그리고 "실재 확인" 칸에 확인한 방법을 적어. 확인 못 한 것은 [미확인]. 마지막에 "이 다섯으로 볼 때 우리 질문에 남는 빈자리"를 두 줄로.
```

**보여야 하는 것:** 검색식 + 논문 표 + 빈자리 두 줄. **왜:** 인용 환각을 막는 습관 — "확인한 방법" 칸이 비어 있으면 그 줄은 없는 것입니다.

## 카드 6 — Critic 이 공격한다 (같은 팀장 창)

```
이제 카드 3의 비판자를 불러라. 방금 Scout 결과를 리뷰어 관점에서 공격해 줘 — (1) 다섯 편 중 실재가 의심되는 것 (2) 검색식이 놓쳤을 선행연구 유형 (3) "빈자리" 주장이 정말 빈자리인지, 아니면 아무도 안 한 이유가 따로 있는지. 지적마다 심각도(치명/주요/경미)를 붙이고, 문제가 없으면 없다고 말해.
```

**보여야 하는 것:** 심각도 붙은 지적 목록. 최소 하나는 "치명" 또는 "주요"가 나오는 게 보통입니다. **왜:** 생성한 쪽이 스스로 검증하지 않는다. 제안한 쪽만 모인 회의는 전부 통과시킵니다.

## 카드 7 — 보고하고 현황판을 그린다 (총괄 창으로 돌아가서)

카드 1~3을 했던 **총괄 대화**로 돌아갑니다.

```
팀장 보고를 받아라: [팀이름_약어] — Scout 이 선행연구 5편과 검색식을 만들었고, Critic 이 [치명 n건 / 주요 n건]을 지적했다. 단계는 그대로, 다음 할 일은 "[Critic 지적 중 하나를 해소하는 행동]".
카드를 갱신해 보여 주고, 그다음 연구실 현황판을 아티팩트(HTML 한 장)로 그려 줘 — 팀 10줄(배정된 팀은 단계·다음 할 일·기다리는 것, 나머지는 미배정), 위에 오늘 날짜와 연구실 이름.
```

**보여야 하는 것:** 갱신된 카드 + 옆에 뜨는 현황판 화면. **왜:** 현황판은 손으로 그리지 않습니다. 카드에서 다시 그려집니다. 보고하지 않은 일은 현황판에 없습니다.

## 카드 8 — 발굴: 후보 셋과 판정

```
발굴팀을 돌려라. 카드 1에서 정한 관심 영역에서 최근 3개월 새 문헌을 웹 검색으로 훑고, 거기서 "이 연구실이 실제로 할 수 있는" 연구 질문 후보 셋을 뽑아 줘. 후보마다 — 질문 한 문장 · 왜 지금인가 · 가장 가까운 선행연구 1편(실재 확인) · 내가 가진 것으로 되는가.
셋을 다 보고 나서 내가 채택 / 보류 / 기각을 하나씩 말하겠다. 판정하지 마라.
```

판정을 말해 줍니다: `1번 보류, 2번 채택, 3번 기각 — 이유는 …`. 그러면 채택된 것이 새 카드가 됩니다.

**보여야 하는 것:** 후보 셋 → 내 판정 → 채택건의 새 카드. **왜:** 발굴팀은 문헌을 쌓는 팀이 아니라 **연구 질문을 발굴하는 팀**이고, 판정은 사람이 합니다.

## 카드 9 — 마무리

```
오늘 만든 것을 정리해 줘 — 연구실 설정 · 프로젝트 카드 · 연구원 정의 셋 · Critic 이 잡은 것 · 발굴 판정. 그리고 이 연구실을 파일로 옮겨 매일 저절로 돌게 하려면 무엇이 더 필요한지 세 줄로.
```

강사가 세 문장으로 닫습니다:
1. **창이 자리다** — 총괄 창과 팀장 창은 서로 모른다. 그래서 카드를 붙여 넣었다.
2. **말로 전하면 사라진다** — 보고하지 않은 일은 현황판에 없다.
3. **생성한 쪽이 검증하지 않는다** — Critic 은 예의가 아니라 구조다.

집에 가서: `github.com/JeonKH81/ai_research_team_light` — 오늘 한 것이 파일과 폴더로 돕니다. `/setup` 이 카드 1, `/project-intake` 가 카드 2, 팀장 창이 카드 4, 현황판이 카드 7입니다.
