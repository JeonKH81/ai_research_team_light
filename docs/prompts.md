# 실습 순서 — VS Code 에서 Claude Code 로 (60분)

VS Code 로 연구실 폴더를 열고, Claude Code 창에 아래 프롬프트를 **순서대로** 입력합니다.
명령어를 직접 칠 일은 없습니다 — 총괄팀장(Claude)이 대신 실행합니다. `[ ]` 안은 자기 것으로 바꿔 넣습니다.

**창은 둘입니다.** 연구실 폴더를 연 창이 **총괄팀장**, 5단계에서 프로젝트 폴더를 새 창으로 열면 그 창이 **팀장**입니다.

| 분 | 단계 | 어디서 |
|---|---|---|
| 0–8 | 준비 — 폴더 열기, 설치 확인 (설치는 **전날** 끝내 온다) | 총괄 창 |
| 8–18 | 1. 연구실 설정 (`/setup`) | 총괄 창 |
| 18–22 | 2. 현황판 열어 보기 | 총괄 창 |
| 22–30 | 3. 내 연구 등록 | 총괄 창 |
| 30–38 | 4. **연구원 하나를 내가 만든다** | 총괄 창 |
| 38–48 | 5·6. 팀장 창 열기 → 연구원 부르기 → Critic 검토 | 팀장 창 |
| 48–54 | 7. 보고 → 현황판 갱신 | 팀장 창 → 총괄 창 |
| 54–58 | 8. 발굴 (시간이 남으면) | 총괄 창 |
| 58–60 | 9. 마무리 | 총괄 창 |

---

## 준비 — 폴더 열기

> **먼저 [준비 문서](prepare.md)의 셋이 끝나 있어야 합니다** — Claude 를 쓸 창(유료 계정) · Python · 내려받은 폴더.
> 하나라도 없으면 여기서 멈춥니다. 당일 현장에서 설치하면 한 시간이 다 갑니다.

받아 둔 폴더(`ai_research_team_light-main`)를 Claude Code 로 엽니다. 고른 길에 따라 여는 법만 다릅니다.

| 길 | 여는 법 |
|---|---|
| VS Code (권장) | 파일 → 폴더 열기 → 그 폴더 → 왼쪽 Claude 아이콘 |
| 터미널 | 그 폴더로 가서 `claude` |

창이 열리면 첫 입력:

```
설치 확인을 돌려서 결과를 보여 줘. ✗ 가 있으면 무엇을 해야 하는지 알려 줘.
```

**보이는 것:** 항목마다 ✓(괜찮음) 또는 ✗(고쳐야 함)가 붙은 목록과, 끝에 "설치는 정상. 다음은 /setup". ✗ 가 있으면 그 줄 옆에 고치는 방법이 같이 나옵니다. **왜:** 시작 전에 무엇이 빠졌는지 30초에 압니다.

> **Python 이 없다고 나와도 실습은 그대로 갑니다.** 총괄팀장이 대신 처리합니다. 문헌 자동 수집 한 가지만 그날 빠집니다. 현장에서 설치하려 하지 마세요.

---

## 1. 연구실 설정

```
/setup
```

총괄팀장이 다섯 가지를 **하나씩** 묻습니다 — 연구실 이름 · 전공 · 팀 이름 규칙 · 발굴팀 관심 영역과 출처 · 랩미팅. 종이 [워크시트](worksheet.md) ①의 답을 그대로 말하면 됩니다. 관심 영역은 말로 설명하면 검색식을 대신 만들어 보여 줍니다.

**보이는 것:** 설정 표 한 장 + 문헌 수집 미리보기 건수. **왜:** 시스템의 값은 사람이 정합니다. 이 답이 `_team/lab.yaml` 한 파일에 남고, 현황판·브리핑·수집이 전부 그것을 읽습니다.

---

## 2. 현황판 열어 보기

```
현황판을 다시 만들어서 열어 줘.
```

**보이는 것:** 브라우저에 현황판 — 팀 10줄 중 `Terra_DEMO-SR` 하나가 진행 중, 나머지 미배정. 팀 줄을 누르면 상세가 나옵니다. **왜:** 이 화면은 손으로 그리지 않습니다. 등록부와 프로젝트 문서에서 매번 다시 만들어집니다.

---

## 3. 내 연구 등록

```
/project-intake
새 연구를 등록한다. 연구 질문: [워크시트 ②의 한 문장]
자료: [있음 — 무엇 / 없음]. 단계: [착상 / 설계 / 자료 / 분석]
모르는 칸은 지어내지 말고 [확인 필요]로 두고, 미배정 팀 하나에 배정해 줘. 끝나면 현황판을 다시 만들어서 열어 줘.
```

**보이는 것:** `projects/P02_…/` 폴더와 `PROJECT.md` 가 생기고, 현황판에 **내 팀 줄**(예: `Mercury_HF-READM`)이 진행 중으로 뜸. **왜:** 프로젝트 문서(`PROJECT.md`)가 정본입니다. 모르는 것을 모른다고 적는 것이 첫 규칙입니다.

---

## 4. 연구원 하나를 내가 만든다 ★ 오늘의 핵심

```
이 연구에 꼭 필요한 연구원을 하나 만들고 싶어. 이름은 [워크시트 ③의 이름, 예: statistician], 하는 일은 [한 줄].
기존 연구원 정의(.claude/agents/ 의 파일 하나)를 본보기로 초안을 만들어서 먼저 보여 줘 — 파일로 만들기 전에.
'절대 하면 안 되는 것' 셋은 내가 직접 정하겠다.
```

초안이 오면 "하면 안 되는 것" 셋을 내 말로 고쳐 넣고:

```
이대로 파일로 만들어 줘.
```

**보이는 것:** `.claude/agents/<이름>.md` 가 생김. **왜:** 역할은 능력이 아니라 **경계**로 정의됩니다. 무엇을 시키느냐보다 무엇을 못 하게 하느냐가 연구의 안전을 정합니다.

---

## 5. 팀장 창 열기

VS Code → **파일 → 새 창** → **폴더 열기** → 방금 생긴 `projects/P02_…` 폴더. 그 창에서 Claude Code 를 열고:

```
당신은 누구입니까? 이번 주에 할 구체적 행동 셋을 말해 주세요.
```

**보이는 것:** "저는 `Mercury_…` 팀의 팀장입니다" + 행동 셋. **왜:** 폴더가 곧 임명입니다. 그 폴더의 `CLAUDE.md` 가 이 창을 팀장으로 만듭니다. 이 창은 총괄 창의 대화를 **모릅니다** — 그래서 상태는 파일에 남겨야 합니다.

---

## 6. 연구원을 부르고, Critic 이 공격한다 (팀장 창)

```
4단계에서 만든 [연구원 이름]을 불러서 [그 연구원의 일 — 예: 이 연구 질문의 선행연구를 찾을 검색식을 만들고 PubMed 에서 실제 논문 5편을 찾아 줘]. 결과는 _workspace/ 에 파일로 남겨 줘. 인용은 실재 확인한 것만, 못 한 것은 [미확인].
```

결과가 오면:

```
방금 결과를 Critic 에게 검토시켜 줘. 리뷰어 관점에서 공격하고, 지적마다 심각도(치명/주요/경미)를 붙이고, 문제가 없으면 없다고 말해 줘.
```

**보이는 것:** `_workspace/` 에 파일 둘(연구원 산출물, Critic 검토). Critic 이 최소 하나는 "주요"를 잡는 것이 보통입니다. **왜:** 생성한 쪽이 스스로 검증하지 않습니다. 제안한 쪽만 모인 회의는 전부 통과시킵니다.

---

## 7. 보고하고 현황판을 갱신한다

팀장 창에서:

```
오늘 한 일을 보고해 줘 — 단계는 그대로, 다음 할 일은 Critic 지적 중 하나를 해소하는 것으로.
```

(팀장이 `report.py` 로 보고를 남깁니다.) 그다음 **총괄 창**으로 돌아가:

```
아침 브리핑을 만들어서 보여 주고, 현황판을 다시 만들어서 열어 줘.
```

**보이는 것:** 브리핑의 "움직인 팀"에 내 팀, 현황판의 다음 할 일이 바뀜. **왜:** 말로 전하면 사라집니다. 보고하지 않은 일은 현황판에 없습니다.

---

## 8. 발굴 — 시간이 남으면

```
발굴팀을 돌려 줘. 최근 일주일 문헌을 모아서 연구 질문 후보를 만들고, 발굴 현황판을 열어 줘.
```

(수집 → `/topic-discovery` → 발굴 현황판 서버. 3~5분.) 화면에서 후보 하나를 **보류**로 눌러 봅니다.

**보이는 것:** 후보 목록과 채택·보류·기각 단추, 누른 판정이 후보 문서에 기록됨. **왜:** 발굴팀은 문헌을 쌓는 팀이 아니라 연구 질문을 발굴하는 팀이고, 판정은 사람이 합니다.

---

## 9. 마무리

```
오늘 만든 것을 정리해 줘 — 연구실 설정, 등록한 연구, 내가 만든 연구원, Critic 이 잡은 것. 그리고 이 연구실을 매일 저절로 돌게 하려면 무엇이 더 필요한지 세 줄로.
```

세 문장으로 닫습니다:
1. **창이 자리다** — 총괄 창과 팀장 창은 서로 모른다.
2. **말로 전하면 사라진다** — 보고하지 않은 일은 현황판에 없다.
3. **생성한 쪽이 검증하지 않는다** — Critic 은 예의가 아니라 구조다.

집에 가서: 본보기 연구를 지우고(총괄 창에 "본보기 연구 정리해 줘") 자기 연구를 넣습니다. 정해진 시각 자동 실행·두 컴퓨터·다른 모델 교차 검토가 필요해지면 정식판(`ai_research_team`)으로 옮깁니다.

## 막히면 (강사용)

| 상황 | 대처 |
|---|---|
| `/setup` 이 목록에 없다 | 열린 폴더가 경량판 폴더가 아니거나, 폴더를 연 **뒤** 새 대화를 열지 않았다. 폴더 확인 → 새 대화 |
| 설치 확인에 ✗ — Python 없음 | 윈도우: python.org 에서 3.9+ 설치(Add to PATH). 시간이 없으면 강사 화면을 보게 한다 |
| 1단계 수집 미리보기가 실패 | 병원망 인증서. "설치를 다시 돌려 줘"(인증서 부품이 들어간다). 그래도 안 되면 넘어간다 — 발굴만 못 할 뿐 |
| 5단계에서 자기를 총괄이라 한다 | 새 창이 아니라 같은 창에서 했거나, 상위 폴더를 열었다. `projects/P02_…` 폴더 자체를 열어야 한다 |
| 6단계 논문이 [미확인]투성이 | 정상 — 그것이 배울 점 |
| 15분 남았다 | 8단계는 건너뛰고 9단계로 |
