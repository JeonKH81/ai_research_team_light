# 핸즈온 — 한 바퀴 돌려 보기

설치가 끝났다는 전제로 시작합니다([설치 문서](설치.md)).
총괄팀장 창에서 **`/hands-on`** 이라고 치면 여기 적힌 순서를 총괄팀장이 하나씩 끌고 갑니다.
이 문서는 **참석자가 화면에서 보는 순서**로 같은 내용을 적어 둔 것입니다 — 따라가다 놓치면 여기서 찾으면 됩니다.

**터미널 창을 두 개 씁니다.**

| 표기 | 어디서 연 창인가 | 무슨 자리인가 |
|---|---|---|
| `[총괄 창]` | 연구실 폴더 `~/ai_research_team_light` | **총괄팀장** — 사람과 말하고 우선순위를 정합니다 |
| `[팀장 창]` | 프로젝트 폴더 `projects/…` | **팀장** — 그 연구 하나를 책임집니다 |

4단계에서 두 번째 창을 엽니다. 그전까지는 `[총괄 창]` 하나뿐입니다.

시간 배분(총 30~40분): 0~2단계 10분 · 3~6단계 15분 · 7단계 10분 · 8단계는 시간이 남으면.

---

## 0. 설치 확인 — 2분

**지금 치는 것** `[총괄 창]`

```bash
python3 _team/scripts/check.py
```

**보여야 하는 것** 줄마다 `✓`. `✗` 가 있으면 그 아래 `→` 가 시키는 대로 고친 뒤 다시 돌립니다.

**왜** 설치가 반쯤 된 채로 실습에 들어가면 뒤에서 엉뚱한 곳이 막힙니다. 여기서 한 번에 걸러 냅니다.

---

## 1. 설정 문답 — 8분

**지금 치는 것** `[총괄 창]` 의 Claude Code 안에서

```
/setup
```

**보여야 하는 것** 다섯 문항을 하나씩 묻고, 마지막에 연구실 이름 · 팀 이름 · 발굴 영역과 출처 · 랩미팅 ·
수집 미리보기 건수가 한 화면으로 정리돼 나옵니다. 답은 `_team/lab.yaml` 에 남습니다.

**왜** 이 연구실이 무엇을 하는 곳인지 알려 주는 자리입니다. 특히 ②전공과 ④관심 영역이 비어 있으면
발굴팀이 낼 후보가 일반론이 됩니다. (이미 해 두었으면 "설정은 돼 있습니다" 한 줄로 넘어갑니다.)

---

## 2. 본보기 현황판 둘러보기 — 2분

**지금 치는 것** `[총괄 창]`

```bash
open _team/dashboard/dist/lab-dashboard.html        # 윈도우: start _team\dashboard\dist\lab-dashboard.html
```

**보여야 하는 것** 팀 열 줄. 그중 `Terra_DEMO-SR` 하나가 진행 중(단계 `protocol`)이고 나머지 아홉은 미배정입니다.
팀 줄을 누르면 그 연구의 상세가 펼쳐집니다.

**왜** *이 화면은 손으로 그리지 않습니다.* 등록부와 프로젝트 카드에서 매번 다시 만들어집니다 —
화면이 틀렸으면 화면이 아니라 카드를 고칩니다.

---

## 3. 내 연구 하나 등록 — 6분  ← 첫 번째 "아" 지점

**지금 치는 것** `[총괄 창]` 의 Claude Code 안에서

```
/project-intake
```

그리고 지금 하고 있는 연구, 또는 해 보고 싶은 연구 하나를 **한 문장으로** 말합니다.
자료가 없어도 됩니다 — 연구 질문 한 문장과 단계(`idea` 또는 `protocol`)면 충분합니다.
미배정 팀 하나(예: Mercury)에 배정됩니다.

**보여야 하는 것** `projects/` 아래 새 폴더와 그 안의 `PROJECT.md`(프로젝트 카드). 이어서 현황판을 다시 만들면:

```bash
python3 _team/dashboard/refresh.py
open _team/dashboard/dist/lab-dashboard.html        # 윈도우: start _team\dashboard\dist\lab-dashboard.html
```

미배정이던 팀 줄 하나가 **내 연구 이름으로 바뀌어** 있습니다.

**왜** 카드가 곧 그 연구의 정의입니다. 연구 질문·설계·현재 단계·대기가 여기 있고,
이후 모든 대화창이 이 카드를 읽고 움직입니다.

---

## 4. 팀장 창 열기 — 3분

**지금 치는 것** **새 터미널**을 하나 더 엽니다 → 이것이 `[팀장 창]` 입니다.

```bash
cd ~/ai_research_team_light/projects/<방금 만든 폴더>
claude
```

그 창에 이렇게 물어봅니다.

```
당신은 누구입니까?
```

**보여야 하는 것** 그 창이 자기를 **`○○_△△ 팀의 팀장`** 이라고 답합니다.

**왜** *폴더가 곧 임명입니다.* 그 폴더의 `CLAUDE.md` 안 '이 세션의 역할' 절이 그 창을 팀장으로 만듭니다.
총괄팀장도 팀장도 불러내는 것이 아니라 **어느 폴더에서 창을 열었는가**로 정해지는 자리입니다.

---

## 5. 연구원 한 명 부르기 — 5분

**지금 치는 것** `[팀장 창]` 에서

```
Scout 을 불러 이 연구 질문의 선행연구를 찾을 검색식을 만들어 줘
```

시간이 있으면 이어서:

```
방금 Scout 결과를 Critic 에게 검토시켜 줘
```

**보여야 하는 것** 결과가 말로만 나오지 않고 `_workspace/` 안에 **파일로** 남습니다.

**왜** 연구원은 필요할 때만 불려 나오고, 결과는 말이 아니라 파일로 남습니다.
그리고 **생성한 쪽이 스스로 검증하지 않습니다** — Scout 이 만든 것은 Critic 이 한 번 공격합니다.

---

## 6. 보고하고 현황판 갱신 — 4분  ← 두 번째 "아" 지점

**지금 치는 것** `[팀장 창]` 에서

```bash
python3 ../../_team/scripts/report.py status <팀이름> --note "Scout 이 검색식 초안을 만들었다"
```

`<팀이름>` 은 3단계에서 배정받은 팀 이름입니다(예: `Mercury`).

그다음 `[총괄 창]` 으로 돌아와서:

```bash
python3 _team/scripts/daily_brief.py --days 1
python3 _team/dashboard/refresh.py
```

**보여야 하는 것** 브리핑의 "움직인 팀"에 그 팀이 뜨고, 현황판의 그 줄이 오늘 날짜로 바뀝니다.

**왜** *말로 전하면 사라집니다.* 대화창끼리는 기억을 나누지 않습니다 —
`[팀장 창]` 이 한 일을 `[총괄 창]` 은 볼 수 없고, **파일에 남긴 것만** 건너갑니다.
총괄팀장은 지켜봐서가 아니라 읽어서 압니다.

---

## 7. 발굴 — 문헌을 모아 후보 만들기 — 10분  ← 세 번째 "아" 지점

**지금 치는 것** `[총괄 창]`

```bash
python3 _team/scripts/discover.py --days 7
```

1단계에서 정한 관심 영역의 최근 일주일 문헌이 `_team/ideas/_incoming/` 에 모입니다.
0건이면 기간을 늘려 봅니다 — `--days 30`. 인터넷이 막히면 `python3 install.py  (인증서 부품을 넣는다 — 맥에서 그래도 안 되면 zsh _team/scripts/fix_certificates.sh)`.

이어서 Claude Code 안에서:

```
/topic-discovery
```

**보여야 하는 것** 모아 온 문헌에서 **연구 질문 후보 카드**가 `_team/ideas/` 에 만들어집니다(3~5분).
Explorer 가 Inventor 와 Surveyor 를 불러 아이디어를 내고 연구 공백을 검증합니다.

그다음 **또 하나의 터미널**에서 발굴 현황판을 엽니다:

```bash
python3 _team/scripts/ideas_server.py      # http://localhost:8790
```

화면에서 후보 하나를 **보류**로 눌러 봅니다 → 카드에 판정이 적히고 판정 기록에도 남습니다.
다 보면 그 창에서 `Ctrl+C` 로 닫습니다.

**왜** 발굴팀은 문헌을 쌓는 팀이 아니라 **연구 질문을 발굴하는 팀**입니다.
모아 오는 일은 지어내지 않도록 기계적으로 하고, 해석과 판정만 사람과 연구원이 합니다.

---

## 8. (시간이 남으면) 랩미팅 — 5분

**지금 치는 것** `[총괄 창]` 에서

```
/lab-meeting
```

**보여야 하는 것** 3단계에서 등록한 연구와 7단계에서 만든 후보를 놓고 채택·보류·기각을 한 번씩.
회의록이 `_team/lab_meetings/` 에 남습니다.

**왜** 판정을 한곳에 모아 두면 큐가 막히지 않습니다. 후보는 매일 쌓이되 결정은 정기 회의에서 한꺼번에 합니다.

---

## 마치며 — 세 문장

1. **창이 자리입니다** — 연구실 폴더면 총괄팀장, 프로젝트 폴더면 그 팀의 팀장.
2. **상태는 파일에 남습니다** — 보고하지 않은 일은 없었던 일이 됩니다.
3. **현황판은 그 파일들에서 매번 다시 그려집니다** — 화면이 아니라 카드를 고칩니다.

3. **자기 연구를 등록합니다.** 총괄팀장 창에서 `/project-intake` — 지금 끌고 있는 연구부터 하나씩.
   정해진 시각 자동 실행·컴퓨터 두 대 운용·다른 모델 교차 검토가 필요해지면 정식판(`ai_research_team`)으로 옮깁니다.
